# 🕵️ Why-Skill · 缺失信息优先的归因审计引擎

> 真相永远在表层叙述之外。大多数工具研究如何把已有的"拼图"拼得更快更准，Why-Skill 研究的是：**当拼图根本不全时，系统性找出"到底少了几块、少了哪几块"**，然后引导用户去现实世界查证。

## 它是什么

Why-Skill 是一个两阶段交互式归因分析引擎：

1. **阶段一（探针）**：不输出任何结论，只输出「缺失信息探针清单」——哪些信息缺失、去查什么（问当事人、查记录、做实验、搜索什么关键词），并检测**单方面叙事**与"过于合理"的**构造痕迹**。
2. **用户查证**：带着探针去现实世界核实（问当事人、查记录、做对照实验），把结果回填。
3. **阶段二（终极审计报告）**：输出系统异常指数、事实与虚构拆解、根因推演（**最可能 → 次可能 → 备选 + 置信度**）、罗生门与双向毒性、双向镜面校准、证据强度与未闭合的环、处方与行动包、免责声明。

适用范围：人际冲突、组织流程异常、物理/设备故障、历史争议等一切"信息不完整"的事件。

## 目录结构

```
rules/           产品逻辑（4 个规则文件：元引擎、逻辑库、解剖刀、审计模板）
why_skill/       CLI 版（main.py + extractor / sanitizer / checker）
web/             Streamlit 网页版（两阶段交互 + 思考折叠 + 成文轮兜底）
pyproject.toml   打包配置
```

**设计原则**：

- 规则是唯一事实来源：CLI 与网页版共用同一套 `rules/*.md`
- system prompt 极短，方法论放 user message（长 system 会稀释约束）
- 全文喂养不截断（DeepSeek 上下文足够容纳长聊天记录）
- 不设输出上限 + **思考轮 / 成文轮兜底**：思考过程完整保留给用户，正文不因思考过长而截断
- 不编造信息，不确定处标注；报告含证据强度分级（铁证/旁证/推测/未知）与"未闭合的环"

## 快速开始

依赖：`pip install streamlit openai httpx`

设置 API Key（环境变量）：

```powershell
$env:WHY_SKILL_API_KEY = "sk-..."
```

### CLI

```powershell
python why_skill/main.py
```

交互方式：

- 粘贴事件描述（多行以 `EOF` 结束），或 `@file 路径.txt` 读取文件（带不带空格均可）
- 阶段一输出探针后，输入补充查证信息（多行以 `EOF` 结束）；直接回车可询问是否跳过
- 阶段二报告自动保存为 `.md` + `.html`（`reports/` 目录，已 gitignore）

### 网页版

```powershell
python web/app.py   # 自动拉起 Streamlit，无需手动输入 streamlit run
```

自带 key 模式：API Key 只存于浏览器会话内存，不落盘、不上传。
